THE ARCHITECTURE (In 30 Seconds)
================================================================================

Path 1: HIGH-CONFIDENCE DETECTIONS (>80% confidence)
├─ Frigate detects motion/person/car
├─ Confidence check: Is it > 80%?
│  └─ YES: Post directly to Discord
│     ├─ Include rich embed with metadata
│     ├─ Embed includes snapshot image
│     ├─ Delivery: < 100 ms
│     └─ Cost: $0.00
└─ Instant notification in Discord channel

Path 2: LOW-CONFIDENCE DETECTIONS (<70% confidence)
├─ Frigate detects ambiguous motion/unknown object
├─ Confidence check: Is it < 70%?
│  └─ YES: Send to Clawdbot for analysis
│     ├─ Include event data and snapshot URL
│     ├─ Clawdbot AI analyzes the image/event
│     ├─ Generates text description
│     ├─ Routes analysis to Discord
│     ├─ Delivery: 5-10 seconds
│     └─ Cost: ~$0.018 per event
└─ Analyzed result in Discord with AI context

COST SAVINGS: 90% reduction by being selective about analysis

================================================================================
5-MINUTE SETUP
================================================================================

1. CREATE DISCORD WEBHOOKS (2 minutes)
   ├─ Go to Discord: Channel → Settings → Integrations → Webhooks
   ├─ Click "New Webhook"
   ├─ Copy webhook URL
   ├─ Store securely (treat like a password)
   └─ Repeat for each channel you want

2. GENERATE SECURE TOKEN (30 seconds)
   └─ Run: openssl rand -hex 32
       Output: a3f7e2c1b9d8f4a6c7e9f1d2a3b4c5d6...

3. CONFIGURE FRIGATE (2 minutes)
   ├─ Reference: frigate-config-example.yml
   ├─ Add Discord webhook URL to notifications
   ├─ Add token to environment or config
   └─ Restart Frigate

4. TEST (1 minute)
   └─ Run: ./discord-webhook-test.sh "your-webhook-url"
       Should see success messages and messages in Discord

================================================================================
KEY CONFIGURATION POINTS
================================================================================

Discord Webhook URL:
├─ Format: https://discord.com/api/webhooks/{webhook_id}/{webhook_token}
├─ Created in: Discord Channel Settings → Integrations → Webhooks
├─ Permission: Delete webhook to revoke access (permanent, no way to recover)
├─ Storage: Treat like a password, use environment variables
└─ Limit: 10 per Discord channel

Frigate Notification Config:
├─ notifications.discord_person: URL for high-confidence
├─ notifications.clawdbot_analysis: URL for low-confidence
├─ conditions: confidence > 80 (adjust thresholds to your needs)
├─ snapshots.enabled: true (required for image delivery)
└─ snapshots.path: /tmp/frigate/snapshots (or custom path)

Clawdbot Hook Config:
├─ hooks.enabled: true
├─ hooks.token: your-secure-token
├─ hooks.path: /hooks (or custom)
├─ hooks.mappings: Route rules based on event source
└─ mappings.deliver: true (send analysis to Discord)

Public Snapshot Access:
├─ Option A: Tailscale Funnel (easiest)
│  ├─ tailscale funnel on
│  ├─ tailscale funnel 5000
│  └─ URL: https://your-machine-name.ts.net/api/events/{id}/snapshot.jpg
├─ Option B: Reverse proxy (HTTPS required)
│  └─ nginx/caddy → localhost:5000 (Frigate)
└─ Without public access: Omit image field from embed (still posts metadata)

================================================================================
TROUBLESHOOTING QUICK REFERENCE
================================================================================

PROBLEM: Image not loading in Discord
CAUSE: Snapshot URL not publicly accessible
FIX: Set up Tailscale Funnel or reverse proxy
    └─ tailscale funnel on && tailscale funnel 5000

PROBLEM: Discord webhook returns 404
CAUSE: Webhook deleted or URL wrong
FIX: Regenerate webhook in Discord, update config

PROBLEM: Discord webhook returns 401
CAUSE: Invalid token or auth header
FIX: Check auth format: Authorization: Bearer TOKEN

PROBLEM: Clawdbot webhook not responding
CAUSE: Gateway not running or token invalid
FIX: clawdbot gateway --force && clawdbot providers status

PROBLEM: Detections not appearing in Discord
CAUSE: Confidence threshold too high or routing misconfigured
FIX: Lower threshold in config, verify webhook URL

PROBLEM: Rate limit errors
CAUSE: Sending >10 requests/sec to Discord webhook
FIX: Add delay between Frigate notifications or use batch mode

FILE PERMISSIONS & SECURITY
================================================================================

After deploying, verify:

Webhook token file:
  ls -la ~/.frigate/webhooks.conf
  # Should show: -rw------- (600)
  # NOT: -rw-r--r-- (644)

Clawdbot config:
  ls -la ~/.clawdbot/clawdbot.json
  # Should show: -rw------- (600)
  # Check: grep "hooks" clawdbot.json doesn't expose token

Git security:
  cat .gitignore | grep -E "webhook|token|credential"
  # Should exclude sensitive files

Environment variables:
  env | grep -i "webhook\|token" | grep -v "^TOKEN=" 
  # Verify sensitive tokens are not logged
